# Orchestral TUI 交互需求 v1.0

状态：需求草案，待实现。日期：2026-09-08。

本版目标：让开发者在一个终端会话内顺畅地描述任务、指定文件、观察执行、纠正方向、切换模型和继续历史工作。设计从 Orchestral 已有的单 Agent、持久会话和可恢复执行出发，围绕“当前在处理什么、是否需要我介入、接下来如何继续”组织界面。

设计约束：pi、Codex、Claude Code 都可作为体验参考。布局、信息优先级和交互取舍必须能由本项目的用户场景解释；保持常见快捷键的可迁移性，同时形成自己的工作记录与会话接续体验。

本文中的版本指 TUI 交互版本，不改变 Agent Protocol 的版本号。验收条目是待满足的要求，不代表现有功能已经通过验证。

2026-09-08 的实现、测试、实际 PTY 回放及剩余验收项见 [实现与验收记录](tui-experience-v1-validation.md)。

## 1. 用户与成功标准

主要用户是每天在项目目录中使用 Agent 编写、检查和修改代码的开发者。首版优先覆盖 macOS 和 Linux 终端；Windows 原生支持单独验证后声明。

核心场景：

1. 在项目中启动，快速确认目录、会话、模型，直接输入任务。
2. 输入 `@` 找到目标文件，输入 `/` 找到操作，无需离开 TUI 查命令。
3. Agent 工作时可以继续编辑指令、提交纠正、查看工具结果和历史。
4. 查看刚才发生的编辑、失败原因和已有检查结果，复制最终回答。
5. 当前任务结束后，在 TUI 中切换模型或恢复另一个会话。

发布要求：这些流程必须通过实际启动 CLI 的 PTY E2E；视觉与终端兼容性另经人工验收。模型回答质量由独立的真实任务评测负责。

### 1.1 本项目的设计取舍

| Orchestral 的实际特点 | 用户需要 | 本版设计决定 |
| --- | --- | --- |
| 一次会话包含多次请求，每次请求都有独立执行记录 | 知道工具和回答属于哪次工作 | 按请求组织正文，保留用户原话、行动和回答之间的归属；旧记录默认收起工具详情 |
| 审批、提问、取消和恢复是日常运行状态 | 迅速知道现在能做什么 | 输入区附近只突出当前动作；需要用户回答时，问题优先于计时、用量等信息 |
| 已有持久历史和中断恢复 | 隔天打开后能直接接上工作 | 恢复首屏展示上次请求、最后确定的状态和可用下一步，定位到待处理位置 |
| 工具结果和最终交付具有不同含义 | 区分“做过什么”和“Agent 怎么总结” | 工具事实与回答分层展示；修改、检查各有来源，不自动生成“目标已达成”徽标 |
| TUI 与 PWA 使用同一套 Host 概念，且可接外部 Agent | 换入口或模型后仍理解当前状态 | 统一会话、运行和待处理事项的表达；有能力才显示操作，不复制 provider 私有面板 |
| 终端主要用于输入和阅读代码，空间有限 | 少切换焦点，少被运行噪声打断 | 一个主输入区、单列正文、按需详情；目录身份与当前动作优先，成本统计移入详情 |

三个核心旅程的首屏重点：开始工作时是“项目 + 会话 + 输入”；执行时是“本次请求 + 当前动作”；回来继续时是“上次停在哪里 + 下一步”。用户不需要理解 Run ID、journal 或 reducer 才能使用它们。

保留 `/`、`@`、常用编辑键等约定以减少迁移成本。首版不采用常驻文件树、多个会话侧栏或大块用量面板；这些会占用主要阅读区域，目前没有足够的本项目场景支撑。

## 4. 视觉方向

### 4.1 布局

- 顶部只占一行，显示项目、会话短标题，空间允许时附分支。完整目录、模型配置和存储位置通过 `/session` 查看；不常驻内部标识。
- 正文采用单列，以用户请求为段落起点，随后排列 Agent 说明、工具行动与回答。通过间距、缩进和细色标表达层次，每条消息不单独套框。
- 输入区固定在底部，采用一条顶部分隔线与明显的输入光标。单行起步，随内容增高，最多占视口三分之一；超出后内部滚动，光标始终可见。
- 输入区上方仅在需要时展示一条当前动作，或完整的待回答问题/审批。问题出现时计时退居次要位置；选择器暂用这一区域，关闭后恢复原焦点。
- 底部常驻一行：实际模型、上下文占用和当前焦点提示。累计 token、费用和缓存数据进入 `/session`，完整规则与 Skills 来源进入 `/context`。
- 启动空白区域给出一条开始提示；恢复会话时替换为接续信息。正常工作后不保留欢迎页占位。
- 80×24 是完整体验基准，120×40 展示更多正文；40×12 保留当前动作、输入和关键状态；沿用 20×6 最低尺寸提示。

布局示意，颜色与宽度以实际终端验收为准：

```text
  Orchestral  orchestral / session recovery           feature/session

  › 修复会话恢复问题，参考 @core/orchestral-runtime/src/session_context.rs

  我先检查会话恢复和上下文投影的连接点。

    ✓ read  core/orchestral-runtime/src/session_context.rs
      248 lines · collapsed

    ✓ edit  core/orchestral-runtime/src/session_context.rs
      +8 −3 · collapsed

    ◌ exec  cargo test -p orchestral-runtime
      running · 4s

  Running tests · 4s                       ctrl+c interrupt
  ────────────────────────────────────────────────────────────────────
  › 请保留现有配置格式的兼容性█
  model: configured-model · context: ~18%    enter steer · / commands
```

文件选择示意：

```text
  Files · session_con                         3 matches
  › core/orchestral-runtime/src/session_context.rs
    core/orchestral-core/src/session_context.rs
    configs/session_context.yaml
  ────────────────────────────────────────────────────────────────────
  › 检查 @session_con█ 的恢复逻辑
  ↑↓ select · tab insert · esc close                 path reference
```

恢复到待回答位置的示意：

```text
  Orchestral  orchestral / session recovery           feature/session

  Resumed · last request: 修复会话恢复问题
  Last confirmed action: read session_context.rs
  Waiting for your answer

  旧配置字段需要保留兼容，还是允许迁移到新格式？

  ────────────────────────────────────────────────────────────────────
  › 保留兼容█
  model: configured-model                     enter answer · f1 help
```

这些路径和统计仅用于需求示意，不代表对应文件均存在或测试已经执行。

### 4.2 样式与信息层次

| 元素 | 要求 |
| --- | --- |
| 正文 | 使用终端默认前景色与背景色，避免强制整屏背景 |
| 用户消息 | `›` 与窄色标表示每次请求的起点，保留可复制的原文 |
| 输入焦点、选中项 | 沿用 Orchestral 现有青色；选中项同时有位置标记 |
| 成功、失败、等待 | 颜色配合符号和文字；单色模式仍能区分 |
| 辅助信息 | 路径、耗时、计数使用次级颜色，浅色主题下仍清晰可读 |
| 工具详情 | 在所属请求内缩进，展开时用轻分隔和行号；成功状态低强调，失败和待处理项更醒目 |
| Markdown | 标题、列表、引用、代码块、链接可辨；常见代码语言高亮，未知语言保留纯文本 |
| diff | 行号与 `+`、`-` 同时保留，不只依赖红绿颜色 |

提供 `terminal`、`dark`、`light` 三种内置配色，默认 `terminal`；自定义主题文件后置。无 True Color、`NO_COLOR` 或符号宽度不可靠时有基础色/ASCII 回退，不依赖 Nerd Font。动画仅作用于正在进行的状态，不闪烁整页或推动正文跳动。

“好看”的验收落在信息层次上：第一眼能定位当前请求和输入位置，第二眼能识别是否需要介入；连续多个成功工具不会压过回答；恢复或错误状态有清楚的下一步。用户只在需要时展开技术细节，正文阅读空间保持稳定。

## 5. v1.0 功能需求

### R01：输入编辑与草稿

- `Enter` 提交；`Shift+Enter` 换行，始终提供 `Ctrl+J` 回退。括号粘贴中的换行不能触发提交。
- 支持左右、`Ctrl+A/E` 到行首/行尾、按词移动和删除、`Ctrl+W/U/K`。全屏主视图的 PgUp/PgDn 与 End 用于正文滚动，候选打开时交给候选列表；帮助明确说明焦点优先级。退格与光标移动不得拆开中文、组合字符或 emoji 字素。
- 上/下先移动多行光标，在首/末行边界访问本会话已提交的输入历史。进入历史前保留当前草稿，向下返回后恢复。
- 粘贴超过 20 行时显示折叠预览和行数，可展开编辑；发送内容保持完整。若超过明确的输入上限，拒绝并保留原草稿，不静默截断。
- 模型选择器、文件选择器、帮助关闭后恢复原草稿、附件引用和光标。会话切换时草稿按会话隔离，v1.0 只承诺进程内保留。
- 流式输出、后台工具状态和通知不能抢走编辑焦点。

### R02：命令发现与选择器

在普通编辑状态下，输入开头的 `/` 打开命令候选；支持过滤、上下移动、Tab 补全和 Enter 执行。每项显示名称、用途、当前是否可用及原因。未知命令提示本地错误并保留输入，不静默发送给模型；`//` 前缀用于发送以 `/` 开头的普通文本，提交时去掉一个 `/`。

| 命令 | 行为 | 可用时机 |
| --- | --- | --- |
| `/help`、`/hotkeys` | 命令与当前快捷键；`F1` / `Ctrl+]` 提供独立入口 | 任意阶段，可独立打开帮助 |
| `/model` | 搜索并切换已配置且当前 Agent 支持的模型 | 无活动 Run |
| `/resume`、别名 `/sessions` | 当前工作区会话选择器 | 无活动 Run |
| `/new` | 创建同工作区新会话 | 无活动 Run |
| `/session` | 当前会话名称/ID、目录、实际存储位置、用量详情 | 任意阶段，只读 |
| `/context` | 已加载规则/Skills 来源、上下文预算与压缩信息 | 任意阶段，只读 |
| `/skills` | 保留已有命令能力 | 查询随时可用，变更遵守现有 Host 限制 |
| `/tools` | 浏览本会话已观察到的工具活动，选择并展开 | 任意阶段，只读 |
| `/copy` | 复制最近一次已提交的 Agent 回答 | 有已提交回答时 |
| `/theme` | 选择内置配色 | 任意阶段 |
| `/quit` | 退出；若有活动 Run，先进入明确的停止与退出流程 | 任意阶段 |

选择器在输入区附近展示，不默认打开全屏面板。无结果、加载中、读取失败、操作不可用均有明确状态。只有候选确认才执行操作；单纯补全命令不能产生副作用。

### R03：文件引用与补全

- 输入 `@` 后按工作区相对路径模糊搜索。多工作区时显示根目录标识；优先列出精确前缀匹配，排序稳定。
- 搜索遵守现有工作区访问边界和忽略规则；默认不遍历 `.git`、构建输出或被忽略目录。扫描与过滤不阻塞输入和取消。
- 确认候选后插入可编辑的路径引用，支持空格、中文、同名文件和多个引用；模型收到可无歧义识别的工作区及路径信息。
- 首版引用明确表示“目标路径”：选择文件不会读取正文，也不显示“已加入全文”。Agent 读取内容仍通过现有受控工具路径，遵守文件权限和预算。
- 提交时检查引用是否仍能解析，失效时定位到对应引用并保留草稿。检查不改变 Host 权限，符号链接不能借此越界。
- 候选面板打开时异步刷新索引，反映新建、重命名及删除；刷新保留仍存在的已选路径，不因排序变化切换选择。
- 文本中的普通 `@` 不被强制解释为附件；只有选择候选后才建立路径引用。

### R04：工具块、输出与滚动

- 按持久记录中的请求归属组织行动与回答；Steer 标记为本次请求的补充。历史缺少可靠归属时保留顺序并说明未知，不根据自然语言内容猜分组。
- 工具块首行显示动作、目标和状态；补充耗时、退出码、变更行数等确实存在的证据。通用/MCP 工具保留可读名称与摘要。
- 成功的 read/search/exec 默认折叠为标题与最多 3 行摘要；失败显示最多 8 行关键输出；编辑显示文件与增删计数，可展开已有 diff 证据。
- `Ctrl+O` 切换本会话工具块的默认展开状态；`/tools` 可选择单个块查看详情。折叠状态仅影响展示，不删除历史或模型上下文。
- 超长结果使用分页或有界窗口。展示“还有 N 行”或“结果已截断”的真实状态；原始内容可取回时提供入口，不可取回时明确说明。不能用重新执行工具来补显示。
- 流式与最终提交内容按稳定标识合并，不能重复展示。每次工具进度更新不能追加一个新的等价工具块。
- 用户滚动离开底部后维持阅读锚点，新输出仅更新“有新内容”提示。`End` 或明确动作返回底部；在底部才自动跟随。展开/折叠、窗口变宽、最终提交都不能无故跳回底部。
- `/copy` 复制已提交原文，不包含角色符号、ANSI、加载光标或折叠提示；失败时保留正文并给出可操作原因，不自动上传内容。
- 回答末尾可附一行本次请求的已记录事实，例如修改文件数和执行命令数，提供详情入口；仅使用类型化证据。没有检查分类依据时只称“命令”，不擅自标成“验证通过”。

### R05：状态栏与上下文可见性

- 顶部保持项目与会话身份；底部保持实际模型、上下文和操作提示；当前动作按需显示在输入区上方。完整目录在 `/session` 可见，长路径优先缩写目录部分。
- token 用量区分本 Run 与本 Session；上下文占用区分精确报告和估计，估计加 `~`。缺失数据显示 `—`，不能显示成零。
- 费用仅在拥有价格和计量依据时展示，并标明估算；订阅、外部 Agent 或未报告成本时不虚构美元值。缺少费用信息不阻塞本版交付。
- `/context` 显示最近一次有效快照的规则来源、Skills、预算、压缩时间和摘要范围；分别标明“已加载”“尚未加载”“不可获取”，不把候选规则当成已生效。
- 压缩、重试、等待审批、等待输入、取消中均显示具体动作。重试显示次数与下一次等待时间，仅使用 runtime 已提供的事实。
- 窄屏依次隐藏分支、上下文比例、模型长名称等次要项；当前阶段和输入操作始终可见。费用、累计用量始终放在详情，完整信息通过命令查看。

### R06：模型与会话选择

- `/model` 展示已配置模型及 provider，支持搜索，标记当前项；配置或鉴权缺失时显示原因。首版不负责新的登录系统或在线模型市场。
- 切换模型只作用于后续 Run，保留当前会话历史；只有 Host 接受后更新选中项。外部 Agent 未提供切换能力时显示不可用，不能只改 UI 标签。
- `/resume` 默认按当前工作区和最近活动排序，展示标题/最近输入摘要、时间和未完成标记；支持搜索。使用稳定 Session ID，不根据名称猜测会话身份。
- 选择会话后加载原有历史；仍有未完成 Run 时，按既有恢复与配置兼容性规则处理。不可恢复时保留历史，说明原因，不静默开始替代 Run。
- 恢复首屏包含上次请求原文的有界预览、最后确定的动作/状态和可用下一步。存在提问或审批时定位到该事项并恢复正确焦点；已结束时定位最近回答并接受新输入。信息从持久记录提取，不额外调用模型编写总结。
- 模型切换、新建和恢复只在无活动 Run 时执行。运行期间提示“任务结束后可切换”，不暗中取消任务或积压一次未确认的切换。
- 会话被其他客户端占用时展示已有 Host 冲突原因，不突破单写入者约束。读取/切换失败后仍能继续使用原会话。

### R07：运行中交互与取消

| 当前焦点/状态 | Enter | Esc | Ctrl+C |
| --- | --- | --- | --- |
| 选择器/帮助 | 确认候选或执行选中动作 | 关闭并恢复草稿 | 关闭当前面板，不连带取消 Run |
| 空闲、已结束 | 提交新 Run | 关闭临时提示，保留草稿 | 有草稿时清空；空草稿时显示退出提示 |
| 运行中 | 发送 Steer | 请求取消当前 Run | 请求取消当前 Run |
| 等待用户回答 | 仅提交该问题的回答 | 请求取消当前 Run | 请求取消当前 Run |
| 等待审批 | 仅在审批选择器明确选择后提交 | 离开详情仍保留审批；主视图中请求取消 | 请求取消当前 Run |
| 取消中 | 不提交新的运行操作，保留草稿 | 保持取消状态 | 不重复发送取消命令 |

- 输入区显示本次 Enter 的用途：`send`、`steer` 或 `answer`。审批为独立焦点，普通输入中的 Enter 不能顺带批准。
- 回答和审批提交后等待确认，旧请求投影不能重新触发提交。问题结束后恢复的草稿需先编辑或移动光标再发送，避免连续 Enter 将旧草稿作为新输入投递。
- Steer 展示“发送中”“已接受”或失败原因；只有确认已应用的事件才能显示“已应用”。失败时保留可编辑内容，支持显式重试；不能自动产生重复输入。
- `Esc` 不再直接退出程序；`Ctrl+D` 在无活动 Run 且输入为空时退出，其他状态按帮助说明处理。快捷键变更必须更新 README 与 TUI 内帮助。
- 取消完成后保留已有输出、未提交草稿和工具真实状态。退出遵守已有进程清理与恢复合同；终端模式必须恢复。
- WaitingInput 中输入文字默认是问题回答，命令通过 `F1` 的独立帮助/操作入口访问，避免把以 `/` 开头的合法回答截走。`Ctrl+]` 是基础终端回退；焦点路由优先于全局快捷键。
- v1.0 不提供 follow-up 队列，帮助中不展示未实现的快捷键。

### R08：终端兼容性与性能

- 窗口缩放后正确重排中文、宽字符、emoji、长路径、表格和代码块；不产生半个字素、残留弹层或不可见光标。
- 所有正文、工具输出、文件名和模型文本经过终端控制字符处理；它们不能变成终端命令或覆盖输入区域。正常文本、换行和代码缩进仍可读。
- 默认保留终端原生文本选择能力，不全局捕获鼠标。v1.0 通过 PgUp/PgDn 和 End 保证应用内滚动，`/copy` 保证完整回答复制；鼠标滚动/选择增强另行验收。
- 支持终端默认配色、基础 ANSI 和 `NO_COLOR`；tmux/SSH 中不依赖系统剪贴板成功。复制失败可查看完整文本，不偷偷改用外部上传。
- 性能目标：本地 10,000 个已索引文件过滤、10,000 条历史投影、每秒 20 次文本增量场景中，输入到可见反馈 p95 ≤ 100 ms，取消按键到控制请求发出 p95 ≤ 100 ms。工具实际停止耗时另行记录。
- 以上为待实测目标：记录机器、终端、输入规模、测量方法，不用固定 sleep 或快照通过来宣称达标。输出与详情内存有界，历史按需投影。

### R09：错误与恢复反馈

- 配置错误、provider 失败、会话锁冲突、流中断和工具失败各自说明发生了什么，并给出当前确实支持的下一步。
- 可恢复中断与已终止失败使用不同状态；局部工具失败不自动把整个任务标成失败。
- 丢失增量后使用已有持久事件/快照重建，保持单条输出与正确审批状态。无法确认的副作用继续显示保守状态，不提供盲目重放按钮。
- “已回复”表示 Run 已交付；“检查通过”必须来自具体检查证据，不能由 DeliveryCommitted 或绿色完成图标推断。

## 6. v1.1 预留合同

### 6.1 follow-up 队列

运行中 `Enter` 继续 Steer；`Alt+Enter` 将下一件任务加入队列，并提供 `/queue` 命令回退。排队条目展示目标会话和内容，支持编辑、删除、暂停；排队后不立即打断现有工具。

队列由 Host 管理并持久化，不只存在于 TUI。当前 Run 正常交付后才允许出队启动下一个 Run；失败、取消、Incomplete、重启和会话占用时暂停并显示状态。重复事件不能重复启动，退出不丢失条目，其他客户端不能同时消费。模型配置绑定时机、出队与 Run 注册的原子边界须在实现前补成版本化合同和恢复测试。

### 6.2 改动与阅读

- `/diff`：先提供只读工作区 diff，并明确比较基准；不能把用户已有改动标成 Agent 本次改动。任务级归属需要独立证据。
- 会话内搜索：定位并保持阅读锚点，保留草稿。
- 外部编辑器：显式启动、返回后恢复终端与草稿，失败不丢输入。
- 快捷键配置：按 action 和焦点绑定，检测冲突，帮助页展示实际绑定。

## 7. 实现边界与交付顺序

| 批次 | 范围 | 可演示结果 |
| --- | --- | --- |
| M1 | R01 基础编辑、R04 请求与行动分组、阅读与折叠、视觉布局、R07 焦点与取消 | 长回答、工具流和多行输入在同一终端中稳定显示；先获得可审查的终端录屏 |
| M2 | R02 命令、R03 文件引用、主题和复制 | `/` 和 `@` 候选实际可用，草稿和焦点无丢失 |
| M3 | R05 状态、R06 模型与会话选择及恢复首屏、R07 投递反馈 | 在 TUI 中完成模型切换、回到待处理事项和 Steer 确认 |
| M4 | R08/R09 剩余兼容性、性能与恢复验收 | 全部 v1.0 场景通过，并记录真实终端限制 |

每批次附带相应单元、快照与 PTY 用例，不把测试统一留到 M4。M1–M3 是内部增量，不能单独宣布 v1.0 完成。

实现约束：

- 保持 `state` 的确定性更新、`render` 的纯展示和 `app` 的副作用边界；选择器、编辑器、工具详情逐步拆成小模块。
- 模型、Session 选择和文件定位通过应用装配的 Host 服务实现。TUI 不直接解析 provider 私有协议，不自行重写 journal 或 runtime 状态。
- 模型切换、上下文统计、详情读取若缺少共享接口，应先补类型化合同；不要从显示文本或 shell 日志反推状态。
- 渲染循环不同步扫描项目、读取大日志或执行 Git；异步结果按请求和会话身份匹配，丢弃过期结果。
- UI 草稿、主题、折叠状态与执行事实分开存储。后续 PWA 可以复用 Host 能力，本版无需同步修改 PWA 界面。
- 已有工具展示、审批、恢复、中文/emoji 和 PTY 清理行为继续回归；不为新界面另建 Agent 执行循环。

### 8.1 自动化验收矩阵

| ID | 场景 | 必须观察到的结果 | 层级 |
| --- | --- | --- | --- |
| T01 | 空会话启动，80×24 / 120×40 / 40×12、三配色、单色 | 布局层次、可见光标、输入提示与窄屏优先级正确 | 渲染快照 + PTY |

| T03 | 命令过滤、无匹配、Esc 退出、未知命令和 `//` | 操作可发现，模型不收到 UI 命令，草稿/光标恢复 | reducer + PTY/模型请求断言 |
| T04 | `@` 文件补全，空格/中文/同名/删除/符号链接/忽略目录 | 引用无歧义，失效可见，不越界、不提前读取正文 | Host 集成 + PTY |
| T05 | 持续输出时滚动、展开工具、缩放窗口、最终提交 | 阅读锚点保持；回到底部才跟随；无重复输出 | reducer + 渲染 + PTY |

| T09 | 模型切换成功/失败/不支持/运行中尝试 | 下个 Run 使用正确模型；失败保持原设置 | Host 集成 + PTY/模型请求断言 |
| T10 | 会话搜索与切换、各自草稿、占用/不可恢复会话 | 正确历史与 Session ID；冲突不丢当前会话 | Host 集成 + PTY |
| T11 | 上下文估计、缺失用量、重复事件、压缩后恢复 | 估计有标识，未知不为零，用量不重复累计 | reducer + 集成 + PTY |
| T12 | `/copy`、无剪贴板、含 ANSI/控制字符的输出 | 复制原文无装饰；失败可见；输出不能改变终端模式 | 单元 + 可控剪贴板集成 + PTY |
| T13 | 取消、退出、provider 失败、可恢复中断、进程重启 | raw mode/光标/备用屏恢复；历史和副作用符合现有合同 | 实际进程 PTY E2E |
| T14 | 大历史、万文件候选、连续增量输出 | 达到已声明响应目标；报告环境、p95 和内存变化 | 独立性能测量 |
| T15 | 多请求、Steer、重放、缺少历史归属或验证证据 | 工具与回答归属正确；未知不猜测；普通交付不冒充验证通过 | reducer + 集成 + PTY |
| T16 | 恢复到已结束、等待回答、等待审批、不可恢复状态 | 首屏呈现实际停止位置与下一步；正确焦点；不额外调用模型 | Host 集成 + PTY |

PTY 必须启动构建出的 `orchestral` 程序，使用临时工作区、真实键盘转义序列、粘贴和 resize。受控 HTTP 模型用于确定性地产生长输出、工具、等待和失败，不向 runtime 注入测试专属提示。验证屏幕投影、请求和持久记录；仅搜索原始 ANSI 输出中的字符串不足以证明当前画面正确。

优先扩展现有 `apps/orchestral-cli/tests/agent_live_e2e.rs` 的 PTY harness，按功能拆用例。剪贴板失败、事件竞态与细粒度焦点组合可在相应边界精确注入，核心用户旅程仍需真实进程覆盖。

### 8.2 人工视觉与真实运行

- macOS 至少检查 Terminal.app、iTerm2 和 Ghostty；Linux 至少一个常用终端，并覆盖一次 tmux/SSH。记录版本、字体、背景、尺寸与键盘协议。
- 实际输入中文和 emoji、选择/复制文本、粘贴 200 行、查看长工具输出，并连续缩放窗口。检查选中项、光标、滚动锚点、浅色/深色/单色对比度。
- 保存空闲、运行、失败、审批、文件选择、模型选择、会话选择的终端截图，以及从提交到切换会话的短录屏。
- 使用有凭据的真实 provider 完成一次多轮编码任务，实际试用补全、Steer、工具展开、模型切换或会话恢复。若网络/凭据阻塞，明确标记未执行或失败，不能以 fixture 通过替代。
- 不要求 SIGKILL 后进程自行清理终端；异常退出测试区分可清理退出与不可捕获终止，重启仍需满足 journal 恢复合同。

### 8.3 发布检查

改动涉及的 CLI、runtime/core 与 conformance 测试全部通过，执行 workspace fmt/clippy 及适用的全量回归。README、快捷键帮助和命令表一致；每个 R/T 条目有结果或明确未完成记录。PTY 通过、视觉通过、真实 provider 验证分别报告。发布前应附可运行的分支与实际终端录屏，便于审查交互效果。
