# 用户接入与 v0.3.0 发布任务

更新时间：2026-09-10。状态：A01–A07 发布准备已完成；尚未正式发布。基线：`391c197` 加本次未提交的清理和发布准备。

## 目标与范围

让第一次接触 Orchestral 的开发者，从官网找到正确安装命令，在 macOS、Linux 或 Windows 上启动，并连接云模型或自己的 OpenAI 兼容服务，完成一次可见的操作、退出并恢复会话。安装、配置、错误提示和文档必须描述实际验证过的行为。

本次目标包含：仓库清理、Windows 支持与实机测试、Shell/PowerShell 安装器、`orch.pandaailabs.com` 官网、URL 接入、CI、README、可审查的 v0.3.0 发布包。官网部署已获授权；Git tag、push、GitHub Release 正式发布仍留到发布决定时执行。

“首次接入完成”不能只用 `--version` 证明：还要通过模型请求、文件工具、会话恢复、错误诊断和对应平台的进程边界验证。下载地址没有已发布资产时，页面应明确说明发布准备状态，安装器应给出可执行的提示。

公开官网使用 `orch.pandaailabs.com`。原计划的 `orchestral.pandaailabs.com` 经检查已用于现有 Cloudflare Access 私有控制入口，因此保留原用途。

## 用户可见内容的质量要求

用户在 2026-09-10 补充：README、安装脚本、启动命令以及所有用户可见内容都必须认真打磨。此要求是 A01–A07 的共同验收门槛。

- 官网 → 安装 → 新终端 → 首次启动 → 配置模型 → 首个任务必须连续；每一步只呈现当前需要的信息。
- 产品名、命令名、参数、目录、版本和平台称呼保持一致；中英文表达自然，不堆内部架构术语。
- 首页和 README 优先给最短可用命令，源码构建、配置全集和高级选项后置。复制按钮、换行、引号与 Shell/PowerShell 语法必须实测。
- 安装输出明确下载版本、安装位置、PATH 状态和下一条命令；没有成功安装时不能出现成功提示。
- CLI `--help`、无配置启动、TUI 空白页、诊断与运行错误形成同一套表达；错误包含原因和可执行的解决步骤。
- 区分“已实现”“已实测”“已发布”；官网和 README 不用完成时描述待办，也不放暂不可用的下载按钮。
- 不把原始堆栈、内部 ID、开发环境绝对路径或敏感配置作为普通用户的排障入口。
- 验收从新用户环境开始，覆盖新 shell、中文/空格目录、网络失败、已有旧版、无凭据和本地 API；不能仅靠代码审查确认文案可用。

## 对照 pi 与 OpenCode

以下依据 2026-09-10 查阅的官方文档，不是三个产品的完整性能评测。Orchestral 现状来自本地代码检查；下表保留改动前的缺口，完成情况和验证范围见末尾验收记录。

| 用户旅程 | pi 的可借鉴做法 | OpenCode 的可借鉴做法 | Orchestral 基线缺口与本次决定 |
| --- | --- | --- | --- |
| 找到并安装 | 官网直接给 Shell、PowerShell 和 npm 命令 | 安装脚本、包管理器和二进制下载 | 现在主要要求源码编译；提供官网、原生归档和两个安装器 |
| 第一次配置 | `/login` 或环境变量，随后选模型 | `/connect` 和 `/models` 将凭据与模型选择拆开 | 已有环境变量和 YAML，但缺少简短接入路径、诊断入口；先补 URL/认证/模型发现和明确示例 |
| 使用本地模型 | `models.json` 配置自定义 baseUrl 和模型；当前无鉴权服务仍需要占位 key | 自定义 provider 的 `baseURL` 和模型列表 | 已有 `endpoint`，却强制 key；支持明确的无鉴权模式，消除假 key 要求 |
| Windows | 文档说明终端和 shell 配置 | 提供原生安装，同时推荐 WSL | 建立原生 MSVC CI、PowerShell 安装和真实 Windows 验收；原生与 WSL 能力分别声明 |
| 理解配置来源 | 用户级和项目级设置 | 文档列出配置位置、合并及覆盖顺序 | 当前发现顺序、自动选 provider、生成文件有理解成本；展示生效配置来源和优先级 |
| 出错后自助恢复 | 文档集中说明登录、设置和平台要求 | CLI 提供认证、模型等管理命令及专门排障文档 | 缺少统一健康检查；补可脱敏的诊断与下一步，不让用户读内部 journal 错误 |
| 持续使用 | 会话内模型选择与会话能力 | 升级、会话与模型命令可发现 | 已有 TUI `/model`、`/resume` 和 CLI sessions；补安装升级、恢复与卸载说明 |

依据：[pi 官网](https://pi.dev/)、[pi 快速开始](https://pi.dev/docs/latest/quickstart)、[pi 自定义模型](https://pi.dev/docs/latest/models)、[pi Windows](https://pi.dev/docs/latest/windows)、[pi 设置](https://pi.dev/docs/latest/settings)、[OpenCode 入门](https://opencode.ai/docs/)、[OpenCode Providers](https://opencode.ai/docs/providers/)、[OpenCode Windows/WSL](https://opencode.ai/docs/windows-wsl/)、[OpenCode 配置](https://opencode.ai/docs/config/)、[OpenCode CLI](https://opencode.ai/docs/cli/)。

推导：本版优先打通“安装 → 配置 → 第一次成功 → 出错可修复 → 再次使用”。大量 provider 数量、插件市场和界面数量不能替代这条路径。沿用项目已有的 Agent/Model/Tool 契约；不为追齐竞品增加第二套运行架构。

验收：本机和 Windows 均完成正常安装、重复安装、路径含空格、校验失败保留旧版本。没有公开 Release 时不得把不存在的下载流程写成已发布可用。

## 测试成本约束

用户在 2026-09-10 补充：后续测试选便宜模型，注意成本。

- 常规 CI、协议、安装与接入测试优先使用确定性本地 HTTP 模拟服务，不调用付费模型。
- 有条件时优先使用现成自部署服务；不为测试自动创建或租用计算资源。
- 需要真实模型验证时选择低成本模型，使用小任务，限制输入、输出、轮次与重试；不运行高价模型、长任务或大规模 coding eval。
- 可用时记录模型、请求次数和 token 用量；没有价格依据时不猜费用。不把模拟服务测试写成真实模型验收。
- 现有 `#[ignore]` live 测试保持 opt-in；发布的常规检查不能隐式消费云额度。
